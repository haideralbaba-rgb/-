# إعداد وكيل الذكاء الاصطناعي "أبو علي" — دليل التشغيل

## 🏗️ البنية المعمارية (كما طُلب تماماً)

```
المتصفح (ChatWidget.tsx)
   │  يرسل رسالة الزبون فقط (بدون أي مفتاح سري)
   ▼
خادمنا (Proxy) — إما:
   • api/chat.js         → Vercel Serverless Function
   • server/index.js     → خادم Express للاستضافة الذاتية
   │  يدمج SYSTEM_PROMPT + الرسائل، ويستخدم API_KEY من env فقط
   ▼
YandexGPT API (llm.api.cloud.yandex.net)
   │  يرد بنص الإجابة
   ▼
خادمنا يعيد { reply: "..." } فقط
   ▼
المتصفح يعرض الرد
```

**الأمان:** مفتاح `API_KEY` موجود فقط داخل `.env` ويُقرأ حصراً عبر
`process.env` من كود الخادم (`api/chat.js` أو `server/index.js`).
كود React في `src/` **لا يحتوي على المفتاح إطلاقاً** ولا يصل إليه المتصفح
أبداً — تحقق من ذلك بالبحث في `dist/` بعد البناء، لن تجد المفتاح هناك.

## ⚠️ خطوة إلزامية ناقصة: `YANDEX_FOLDER_ID`

مفتاح `API_KEY` الذي زوّدتنا به هو مفتاح **Api-Key** خاص بـ Yandex Cloud
(YandexGPT). لكن Yandex Cloud تتطلب أيضاً **معرّف المجلد (Folder ID)**
مع كل طلب — وهذا غير مزوَّد حالياً.

بدون هذا المعرّف ستفشل كل الطلبات ويظهر للزبون رسالة خطأ ودّية بدل رد
الذكاء الاصطناعي (تم تصميم الواجهة لتفشل بأمان دون كسر الموقع).

### كيف تحصل عليه:
1. سجّل الدخول إلى [console.yandex.cloud](https://console.yandex.cloud)
2. من القائمة العلوية اختر اسم المجلد (Folder) الذي أنشأت فيه حساب الخدمة
3. انسخ الـ **Folder ID** (يبدأ عادة بـ `b1g...`)
4. افتح ملف `.env` في جذر المشروع وضع القيمة:
   ```
   YANDEX_FOLDER_ID=b1gxxxxxxxxxxxxxxxx
   ```

تأكد أيضاً أن حساب الخدمة (Service Account) المرتبط بالمفتاح يملك صلاحية
`ai.languageModels.user` على الأقل.

## 🚀 خيار النشر 1: Vercel (الأسهل والموصى به)

هذا المشروع بُني كموقع ثابت (Vite)، لكن Vercel يكتشف تلقائياً أي ملف
داخل مجلد `api/` وينشره كـ Serverless Function دون أي إعداد إضافي.

1. ارفع المشروع إلى GitHub
2. اربطه بمشروع جديد على [vercel.com](https://vercel.com)
3. من إعدادات المشروع → Environment Variables أضف:
   - `API_KEY` = (المفتاح الذي زوّدتنا به)
   - `YANDEX_FOLDER_ID` = (معرّف المجلد)
   - `YANDEX_MODEL` = `yandexgpt` (اختياري، هذه القيمة الافتراضية)
4. Deploy. الواجهة ستستدعي تلقائياً `/api/chat` على نفس النطاق.

لا حاجة لتغيير أي كود في الـ Front-end — `chatService.ts` يستخدم
المسار النسبي `/api/chat` افتراضياً.

## 🖥️ خيار النشر 2: خادم Express ذاتي الاستضافة

إن كنت تفضل تشغيل خادم Node خاص بك (VPS، Railway، Render...):

```bash
# تأكد من تعبئة .env أولاً (API_KEY + YANDEX_FOLDER_ID)
node server/index.js
```

سيعمل الخادم على `http://localhost:8787` (أو المنفذ الذي تحدده في `PORT`).

بعدها أخبر الواجهة الأمامية بعنوان الخادم عبر متغير بيئة **علني** خاص
بـ Vite (وليس بالمفتاح السري نفسه):

```
# ضمن ملف .env في جذر مشروع الـ Front-end (Vite)
VITE_CHAT_API_URL=https://your-server-domain.com/api/chat
```

> ملاحظة: أي متغير يبدأ بـ `VITE_` يُضمَّن في حزمة الـ Front-end
> ويكون مرئياً للمتصفح — هذا مقصود هنا لأنه مجرد **عنوان URL** للخادم،
> وليس مفتاحاً سرياً. المفتاح السري نفسه يبقى فقط داخل الخادم.

## 🧪 الاختبار محلياً

بما أن هذا المشروع مبني بـ Vite وحده (بدون خادم مدمج)، لتجربة الشات
بالكامل محلياً تحتاج تشغيل الخادم بشكل منفصل:

```bash
# طرفية 1 — تشغيل خادم الذكاء الاصطناعي
node server/index.js

# طرفية 2 — تشغيل الموقع
npm run dev
```

ثم أضف في `.env`:
```
VITE_CHAT_API_URL=http://localhost:8787/api/chat
```

## 🛡️ ماذا يحدث إن لم يتم الإعداد بعد؟

الواجهة لا تنهار أبداً. إن لم يُنشر الخادم بعد، أو كان `YANDEX_FOLDER_ID`
فارغاً، سيظهر للزبون رد ودّي من "أبو علي" يفيد بتعذر الوصول للخدمة حالياً،
مع اقتراح التواصل عبر واتساب (إن كان مفعّلاً في `restaurantConfig.ts`).

## 📝 تعديل شخصية الوكيل مستقبلاً

كل نص الشخصية والمنيو المستخدَم في الردود موجود في مكان واحد فقط:

```
api/_shared/assistantConfig.js  →  SYSTEM_PROMPT
```

عدّل هذا الملف فقط، ويطبَّق التغيير تلقائياً على كل من Vercel وExpress
لأن كليهما يستوردان من نفس الملف المشترك.
